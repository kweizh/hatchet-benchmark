# Basic Hatchet Task with Python SDK ## Background Hatchet is a distributed task queue and durable execution engine. The `hatchet-sdk` Python package allows you to define tasks as Python functions, register them on a worker, and invoke them through Hatchet Cloud. This task asks you to build a minimal end-to-end example: define one task, register a worker, run the task once against Hatchet Cloud, and save the result. You will use the managed Hatchet Cloud control plane (the default server endpoint baked into the SDK). Do **NOT** configure a custom `HATCHET_CLIENT_HOST_PORT`, `server_url`, or any other server-address override. ## Requirements * Use the `hatchet-sdk` Python package to define a task named `simple_greeting`. * Input: a JSON object of the form `{"name": str}`. * Output: a JSON object of the form `{"greeting": "Hello, <name>!"}` where `<name>` is the value of the input `name` field, inserted verbatim (no extra whitespace, no surrounding quotes). * Write a runner script that: 1. Reads `ZEALT_RUN_ID` from the environment. 2. Creates a Hatchet worker whose worker name is `basic-task-worker-${ZEALT_RUN_ID}`, registers the `simple_greeting` task on it, and starts it (in the background or in a separate thread/process) so the task can be executed. 3. Triggers exactly one run of `simple_greeting` with input `{"name": "World"}` against Hatchet Cloud and waits for the run to complete. 4. Writes the task's output (a JSON object containing the `greeting` field) to `/tmp/result.json` as valid JSON. 5. Shuts down the worker cleanly and exits with code 0. * The result must come from an actual Hatchet Cloud task run (no mocking, no local function call shortcut). ## Implementation Hints * Authentication uses the `HATCHET_CLIENT_TOKEN` environment variable, which is already set in the environment. Do **NOT** hardcode any token value. * Do **NOT** set a server address. The default endpoint configured in the SDK points at Hatchet Cloud; leave it alone. * A typical Python program defines `hatchet = Hatchet()`, decorates a function with `@hatchet.task(...)`, creates a worker via `hatchet.worker(...)` with the task in its workflow list, and starts the worker. To trigger a run from the same process, you can run the worker in a background thread/subprocess and call the task's `run` / `aio_run` method, which returns the task's output when the run finishes. * Make sure the script terminates after the result is written; do not leave the worker process blocking. * Install dependencies with `pip install hatchet-sdk`. ## Acceptance Criteria * Project path: /home/user/myproject * Log file: /home/user/myproject/output.log (the runner script's stdout/stderr must be appended here when executed by the grader) * Result file: /tmp/result.json * The result file at `/tmp/result.json` must be valid JSON and contain a top-level field `greeting` whose value is exactly `Hello, World!`. * The task and worker must be created using the `hatchet-sdk` Python package, registered against Hatchet Cloud (default server), and authenticated using the `HATCHET_CLIENT_TOKEN` environment variable read from the real environment. * The worker name registered on Hatchet Cloud must be `basic-task-worker-${ZEALT_RUN_ID}` where `${ZEALT_RUN_ID}` is read from the `ZEALT_RUN_ID` environment variable.
