# Hatchet Bulk Run with Python SDK ## Background Hatchet is a distributed task queue and durable workflow engine. When you need to execute the same task with many different inputs, calling the task one input at a time is wasteful — every invocation incurs network roundtrips to the Hatchet engine. Hatchet provides bulk run helpers on the Python SDK that submit many inputs in one shot and wait for all of the results. In this task you will implement a small Hatchet project that defines a `double_value` task, registers a worker for it, and a runner that uses the **bulk run API** to fan out 10 inputs in a single call and writes the results into a JSON file. ## Requirements * Use the `hatchet-sdk` Python package against **Hatchet Cloud** (no self-hosted server; the SDK default server address is used). * Define a single Hatchet task that accepts an input `{"n": int}` and returns an output `{"result": int}` where `result == n * 2`. * Provide a worker entrypoint that registers the task and runs the worker process. The worker must be started in the background before the runner is invoked. * Provide a runner entrypoint that submits **a single bulk run of exactly 10 inputs** with `n = 1, 2, 3, ..., 10` using the SDK's bulk run API (for example `double_value.run_many([...])` or `await double_value.aio_run_many([...])`, building each item with `double_value.create_bulk_run_item(input=...)`). * The runner must collect all 10 results returned by the bulk call and write them to `/tmp/results.json` as a JSON array of objects ordered by `n` ascending: ```json [ {"n": 1, "result": 2}, {"n": 2, "result": 4}, ... {"n": 10, "result": 20} ] ``` * After the runner finishes and `/tmp/results.json` is written, the task is considered complete. You must actually start the worker and execute the runner — do not pre-compute results without going through Hatchet. ## Implementation Hints * Authenticate with the `HATCHET_CLIENT_TOKEN` environment variable — the SDK picks this up automatically; do not hardcode the token and do not pass a custom server URL. * Define the task with `@hatchet.task(...)` on a `Hatchet()` client instance. Use a Pydantic `BaseModel` (or a plain dict) for the input type so the bulk helper can serialize it. * Start the worker **before** the runner submits the bulk call, otherwise the runs will time out. Give the worker a few seconds to register before triggering the runs. * Use the bulk API in **one** call. Do **not** loop over `run()` 10 times — that would defeat the purpose of bulk submission. * The order of results returned by `run_many` / `aio_run_many` follows the order of the input list, but the verifier reads `/tmp/results.json` and checks the mapping `n -> 2n`, so sort by `n` before writing the file if you are unsure. * Each object in the output JSON must have exactly the keys `n` and `result`, both as integers. ## Acceptance Criteria * Project path: /home/user/myproject * Log file: /tmp/results.json * The Hatchet worker must be implemented and runnable; the runner must trigger a real bulk run against Hatchet Cloud using `HATCHET_CLIENT_TOKEN` from the environment. * The file `/tmp/results.json` must exist and contain a JSON array of exactly 10 objects. * Each object in the array must have exactly the integer fields `n` and `result`, with `result == n * 2`. * The array must contain every value of `n` from 1 through 10 inclusive (each appearing exactly once), ordered by `n` ascending. * The bulk run must be submitted via the Hatchet Python SDK's bulk API (e.g. `run_many` or `aio_run_many`) in a single call.
