## What `main.py` does

1. **Task definition** — `slow_task` is defined via `@hatchet.task(...)` with:
   - `name=f"slow_task-{RUN_ID}"` — includes the `ZEALT_RUN_ID` env var so concurrent cloud runs don't collide on the workflow registry.
   - `execution_timeout=timedelta(seconds=5)` — Hatchet will cancel the task after 5 s.
   - `retries=0` — no retries after the timeout.
   - Body calls `time.sleep(20)`, which will always be interrupted by the 5-second timeout.

2. **Background worker** — `_run_worker()` creates a `hatchet.worker(...)` registered with `slow_task` and calls `worker.start()`. This is launched in a **daemon thread** so it runs its own asyncio event loop independently of the main thread, and the process can exit normally after the main thread finishes.

3. **5-second startup delay** — `time.sleep(5)` gives the worker time to connect to Hatchet Cloud and register the workflow before the trigger call is made.

4. **Trigger & result** — `slow_task.run()` blocks the main thread until Hatchet reports the outcome. Since the task times out:
   - The exception (a `TaskRunError` or `FailedTaskRunExceptionGroup`) is caught.
   - `/tmp/result.json` is written as `{"timed_out": true, "error": "<message>"}`.
   - If the task unexpectedly succeeded, `{"timed_out": false}` is written instead.

5. **Clean exit** — the script always exits with return code 0.
