### How it works

**`task.py`**
- Reads `ZEALT_RUN_ID` from the environment and builds `RATE_LIMIT_KEY = f"ext-api-{RUN_ID}"`.
- Creates a `Hatchet(debug=True)` client.
- Defines `call_external_api` decorated with `@hatchet.task(name="call_external_api", rate_limits=[RateLimit(static_key=RATE_LIMIT_KEY, units=1)])`.
- Each invocation appends one UTC ISO-8601 timestamp line (`2025-05-25T12:34:56.789012Z`) to `/tmp/rate_log.txt` using append mode.

**`worker.py`**
- Calls `hatchet.rate_limits.put(RATE_LIMIT_KEY, 5, RateLimitDuration.MINUTE)` to register the static limit on Hatchet Cloud.
- Starts a worker with `slots=20` (so the only throttle is the Hatchet rate limit, not local capacity).
- `worker.start()` blocks; this module is always run inside a child process.

**`main.py`**
- Clears `/tmp/rate_log.txt`.
- Spawns the worker in a `multiprocessing.Process` (using `spawn` start method to avoid gRPC/asyncio conflicts).
- Waits 10 s for the worker to connect, then dispatches 15 runs in parallel via a `ThreadPoolExecutor(max_workers=15)` calling `call_external_api.run({})`.
- Waits for completion: first tries `.result()` on each run reference (SDK-native blocking wait); falls back to polling the log file every 10 s if any refs error.
- Timeout is 300 s (5 minutes).
- Verifies the log has ≥ 15 lines, terminates the worker, and exits 0.

**`run.sh`**
- Validates `HATCHET_CLIENT_TOKEN` and `ZEALT_RUN_ID` are set.
- Auto-installs `hatchet-sdk` if missing.
- `cd`s to the project directory (so relative imports resolve) and `exec python3 main.py`.
