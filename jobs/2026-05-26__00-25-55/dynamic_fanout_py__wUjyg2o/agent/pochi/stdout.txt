A *parent* workflow receives a batch of integers, spawns one *child* workflow per item to perform a computation, then aggregates the results in the original input order. This pattern is heavily used in real Hatchet applications — for example, when a parent task receives a list of documents at runtime and fans out one OCR/extract job per document. Crucially, the number of children is **not known at workflow-definition time**: it depends on the runtime input. Hatchet Cloud is already provisioned, and the worker authentication token is provided via the `HATCHET_CLIENT_TOKEN` environment variable. You do NOT need to set a server URL — the Python SDK targets Hatchet Cloud by default. ## Requirements * Implement two Hatchet workflows using the Python SDK (`hatchet-sdk`): 1.
