# Hatchet Static Rate-Limited Task (Python) ## Background Hatchet is a distributed task queue and workflow engine that supports first-class rate limiting. Static rate limits are declared on the `Admin` client (via `hatchet.rate_limits.put(...)`) before the worker starts, and individual tasks consume units from a named limit via the `rate_limits=[RateLimit(static_key=..., units=...)]` configuration. When more runs are dispatched than the limit allows, Hatchet re-queues them until capacity becomes available, which is exactly the behaviour this task verifies end-to-end against Hatchet Cloud. Your job is to implement a small Python project that defines a single rate-limited task called `call_external_api`, registers a static rate limit, starts a worker, and triggers many runs in parallel so that the rate limit visibly throttles execution. ## Requirements * Use the `hatchet-sdk` Python package and connect to Hatchet Cloud using the `HATCHET_CLIENT_TOKEN` from the environment (no server URL needed). * Read the current run-id from the `ZEALT_RUN_ID` environment variable and build the static rate-limit key as `ext-api-${ZEALT_RUN_ID}` so concurrent trials do not interfere with each other. * Register a static rate limit on this key with `limit=5` and `duration=RateLimitDuration.MINUTE` using `hatchet.rate_limits.put(...)` before starting the worker. * Define a Hatchet task named `call_external_api` that: * Is decorated with `rate_limits=[RateLimit(static_key="ext-api-${ZEALT_RUN_ID}", units=1)]` (with `${ZEALT_RUN_ID}` interpolated at runtime). * On each invocation appends one line to `/tmp/rate_log.txt`. Each line must be the UTC start timestamp of that invocation in ISO 8601 format with a trailing `Z` (e.g. `2025-05-25T12:34:56.789012Z`). * Writes must be append-only and safe under concurrent invocations. * Provide a single orchestration entrypoint that, when executed, performs the full end-to-end flow against Hatchet Cloud: 1. Clears any pre-existing `/tmp/rate_log.txt`. 2. Registers/updates the static rate limit. 3. Starts a Hatchet worker (in the same process or a child process) that exposes the `call_external_api` task. 4. Triggers 15 runs of `call_external_api` in parallel (or in very rapid succession) from the same process. 5. Waits until all 15 runs have completed. 6. Exits with status 0 only after `/tmp/rate_log.txt` contains 15 timestamp lines. * No mocking: the worker MUST connect to Hatchet Cloud and runs MUST be dispatched and executed through Hatchet. ## Implementation Hints * The `hatchet-sdk` Python package exposes `Hatchet`, `Context`, `RateLimit`, and `RateLimitDuration` at the top level. * Use `hatchet = Hatchet(debug=True)` (or similar) and then `hatchet.rate_limits.put(KEY, 5, RateLimitDuration.MINUTE)` to declare the static limit. * Attach the limit to your task by passing `rate_limits=[RateLimit(static_key=KEY, units=1)]` to the `@hatchet.task(...)` decorator. * Use `hatchet.worker("rate-limit-worker", slots=20, workflows=[call_external_api])` so the local worker has enough slots that any throttling is due to the Hatchet rate limit and not local capacity. * To start the worker and trigger runs from the same script, run the worker in a background thread/process (e.g. via `multiprocessing.Process` or `worker.start()` in another process). Make sure to terminate the worker after the runs complete. * To trigger 15 runs in parallel, prefer the SDK helpers such as `call_external_api.run_many([...])` or call `call_external_api.run()` from a thread pool. Make sure the calls are non-blocking enough that they all reach Hatchet within a few seconds. * Append to `/tmp/rate_log.txt` using `"a"` mode and a single `write` call per invocation; using a short `with open(...)` block is sufficient because Hatchet runs each task in its own process step. * Because the static rate limit is `5 per minute`, expect 15 runs to take at least \~2 minutes to fully drain. Configure your wait/timeouts accordingly (e.g. wait up to 5 minutes). ## Acceptance Criteria * Project path: /home/user/myproject * Log file: /tmp/rate\_log.txt * Orchestration entrypoint: `bash /home/user/myproject/run.sh` runs the full flow (register rate limit, start worker, trigger 15 runs, wait for completion) and exits 0 on success. * The rate-limit key registered on Hatchet must be `ext-api-${ZEALT_RUN_ID}` where `${ZEALT_RUN_ID}` is the value of the `ZEALT_RUN_ID` environment variable. * The static rate limit must be `limit=5` with `duration=RateLimitDuration.MINUTE` and the task `call_external_api` must consume `units=1` per invocation via `RateLimit(static_key=..., units=1)`. * After the entrypoint finishes, `/tmp/rate_log.txt` must contain exactly 15 non-empty lines, each line a single UTC ISO 8601 timestamp ending in `Z` (e.g. `2025-05-25T12:34:56.789012Z`). * The timestamps in the log file must show evidence of rate limiting: the difference between the latest and earliest timestamp must be at least 50 seconds, and no rolling 60-second window may contain more than 5 timestamps. * The orchestration must complete (exit 0) within 5 minutes wall-clock time.
